읽는 법

  • p50 · p95 = 선형 보간 백분위(성공한 측정만, 정렬 뒤 위치 (n − 1) × p / 100). 오류가 난 반복은 빼지 않고 "오류" 칸에 개수와 메시지로 남깁니다.
  • M-07 전체 처리시간 = 상태 변경 처리 시작부터 DOM 반영 완료까지를 performance.now()로 잰 값입니다. 화면 표시(페인트) 완료 시간이 아닙니다. requestAnimationFrame 콜백으로 페인트 완료를 단정하지 않습니다.
  • M-04 · M-05 · M-06은 B-01 ~ B-05에서 단계 함수(VNode 생성 → diff → patch)를 엔진 update()와 같은 순서로 직접 불러 따로 잽니다. B-06 · B-07은 엔진 경로(setter · 이벤트 → 렌더)를 그대로 지나므로 단계별 시간이 없고(—) 전체 시간만 있습니다.
  • M-02 DOM 작업 = patch 한 줄(복합 작업 하나: INSERT는 하위 트리를 통째로 만들어 붙임)의 종류별 개수입니다. 다른 구현의 DOM API 호출 1개와 같은 단위가 아닙니다. MutationObserver 기록 수 · 추가/제거된 노드 수는 따로 적습니다 (복합 INSERT는 하위 노드까지 한 덩어리로 1개).
  • DOM 작업 집계 · 노드 참조 유지(M-03) · 최종 화면 정확성은 시간을 재지 않는 "집계 실행" 한 번에서만 구합니다. 시간 측정 반복에는 관찰 콜백 · MutationObserver를 붙이지 않아 patch 시간에 섞이지 않습니다.
  • B-07의 M-07에는 앱 자신의 effect(탭 제목 · 기록판 쓰기) 시간이 들어갑니다. 기록판에 effect가 직접 쓴 변경은 patch가 아니므로 M-02 · MutationObserver 집계에서 빼고, 비고에 "기록판 직접 쓰기 N건"으로 따로 적습니다.
  • B-01 ~ B-05의 이벤트 핸들러는 항상 같은 함수라 핸들러 교체(SET_EVENT) 비용은 이 측정에 들어가지 않습니다.
  • 항목 수 ≠ 노드 수입니다 (항목 1개 = 노드 5개). 이 결과만으로 알고리즘 우열 · "Virtual DOM이 항상 빠르다"를 판단하지 않습니다. 측정하지 않은 수치는 쓰지 않습니다.

## 이해 체크포인트 (2.5단계)
- 마스터가 공부 질문 1개 후 병합 (가) / 바로 병합 (나)를 물음 → A (원문): "(가)로 진행하자"

  - A (원문): "이미 코드에 예약을 걸었기 때문에(1번)" → 맞음(①, 첫 호출의 ②가 표시를 남겨서). "언제 렌더하나"는 빠짐 → 마스터가 호출 순서 표로 ③을 되물음
  - A (원문): "그러니까 scheduled 배열에 들어간 함수들이 전부 끝나야 렌더링이 발생한다는 거지?" → 일부 다름: scheduled는 함수 목록이 아니라 "예약이 걸린 컴포넌트" 표시. 렌더는 [+3] 클릭 핸들러(setter 3줄)가 끝난 직후 한 번, 그때 count = 3. 마스터가 시간 순서로 설명하고 한 줄 요약 확인을 물음
  - 사용자 질문 (원문): "세터 함수가 뭐였지?" → 마스터 설명: useState가 돌려주는 두 번째 값 = 상태를 바꾸는 함수 (setCount). 부르면 칸 값을 바꾸고 다시 그리기를 요청
  - A (원문): "값을 바꾸고 렌더 예약을 거는 함수구나. 그러니까 scheduled 배열에 세터 함수들이 전부 끝나야 헨더링 되는거지?" → setter 정의 맞음. 시점(setter 호출이 전부 끝난 뒤 렌더)도 맞음. 보충: scheduled에는 setter가 아니라 "App 예약됨" 표시 하나만 들어감 (보충 설명 있음)
  - 최종 요약 (마스터 정리, 사용자 확인 "어어 main에 병합하자"): "setter는 값을 바꾸고 렌더 예약을 거는 함수다. 같은 컴포넌트는 예약 표시가 하나만 남고, setter들이 전부 끝난 뒤(클릭 핸들러가 끝난 뒤) 렌더가 한 번 일어난다."

- 시나리오 하나 = `e2e/*.spec.ts` 테스트 하나. 테스트 이름은 시나리오 문장 그대로
- `QA-N`은 이 표의 행 번호일 뿐이고, 근거 ID는 PRD ID · T-ID(`P2-xx` · `T-xx` · `D-0x`)와 PRD 절(§4.2 · §4.3 · §5 · §6.2)만 쓴다. 번호는 이번 task 새 번호다 (인수 QA-1부터, 공격적 QA-A1부터, 확장은 QA-20 · QA-21)
- 화면 약속 `data-testid` · 상태 이름은 `dev_todo.md` 「공통 약속」의 표를 따른다. 기록판 칸(`log-render` · `log-effect` · `log-memo` · `log-patch` · `log-patch-events`)과 `counter-value` 글은 **숫자만** 들어 있다. 로드 직후 값: 카운터 0 · 이름 빈칸 · 빈 목록(안내 `todo-empty` "할 일이 없어요") · render 1 · effect 1 · memo 1 · patch 0 · patch-events 0 · 탭 제목 `카운터 0 - Phase 2`
- 기록판 칸 구성(effect · patch 칸은 effect가 직접 씀, patch 줄 수를 전체 `log-patch` · 이벤트 교체 `log-patch-events`로 나눔 — 테스트 케이스 확인 2 · 3), 빈 이름 안내 · 빈 할 일 [추가] 무시 · 경계 이동 무시 · 처음엔 빈 목록(테스트 케이스 확인 5)은 확정된 약속이다
- 렌더 횟수는 `log-render` 칸에서 읽는다 (Dev-17 · 18 · 19에서 기록판이 생기기 전에는 임시 `window.__renderCount`, Dev-21에서 칸으로 바꾸면서 e2e도 함께 고침)
- **공통 확인 (모든 스펙 · 모든 테스트)**
  - 콘솔 `error`(`console.error` · `pageerror`)가 한 건이라도 있으면 실패한다 (`phase1-helpers.ts`의 `test` 확장 재사용)
  - **dialog가 뜨면 실패한다.** Phase 2 검증 페이지에는 alert가 없으므로 `captureAlert`로 선언하는 시나리오가 없다
  - QA-1 · QA-A4는 콘솔 경고도 0건
- **노드 참조**: `holdNodes` · `sameNode`로 페이지 안 JS 변수에 붙잡아 두었다가 `===` 비교 (`{ area: 'app-root' }`). DOM 속성을 쓰지 않는다
- **DOM 변경 관찰**: `app-root`에 `MutationObserver`를 심는다. **기록판(`log-*`) 안은 따로 센다** — 기록판의 effect · patch 칸은 effect가 `textContent`로 직접 쓰기 때문에(초안 ④-2, 테스트 케이스 확인 2 확정) 본문 변경 수와 섞으면 안 된다. 본문 = 기록판을 뺀 나머지. 입력창 `value` · 체크박스 `checked`는 프로퍼티라 `attributes` 기록이 생기지 않는다
- 입력 · 클릭은 사용자처럼: `fill` · `pressSequentially` · `click`. 입력창 포커스를 옮기지 않고 다른 상태를 바꿔야 할 때만 `page.evaluate(() => el.click())`로 버튼을 누른다 (`el.click()`은 포커스를 옮기지 않음)

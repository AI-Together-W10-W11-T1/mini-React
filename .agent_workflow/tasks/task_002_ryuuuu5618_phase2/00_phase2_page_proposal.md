# Phase 2 검증 페이지 구성안 (`fixtures/phase2-app`)

- task: `task_002_ryuuuu5618_phase2` · 0단계 · 상태: **사용자 확인 (2026-11-11, "어어 그럼 그렇게 진행하고")** → `01_request_spec.md`에 반영
- 배경: 피그마 같은 편집기는 미니 React 구현이 끝난 뒤 따로 만들 시연 앱이다. Phase 2는 Phase 1처럼 **엔진 + 검증 페이지**로 만든다.
- 목표: Hook과 자동 갱신(상태 변경 → 새 VNode → diff → patch)을 기능별로 하나씩 눈으로 확인한다.

## 1. 전체 구조

```
App (루트: 상태 · Hook을 모두 가짐)
├─ CounterPanel   ① 카운터
├─ GreetingPanel  ② 입력창
├─ TodoPanel      ③ 목록
│   └─ TodoRow    (항목 한 줄, key = 항목 id)
└─ LogPanel       ④ 기록판
```

- 자식 컴포넌트는 **props만 받는 순수 함수**다. 상태 · Hook을 쓰지 않는다 (P2-07 · P2-09).
- 자식이 버튼을 누르면 루트가 내려 준 함수(`onIncrease` 같은 props)를 부르고, 루트가 setter로 상태를 바꾼다 (Lifting State Up).

## 2. 칸별 구성

### ① 카운터 (`CounterPanel`)

| 화면 | 동작 |
| --- | --- |
| 숫자 `0` | 현재 카운터 값 |
| [+1] | `setCount(c => c + 1)` 한 번 |
| [+3] | `setCount(c => c + 1)`을 **세 번** 연달아 → 3 증가, 렌더도 3번 (즉시 동기) |
| [그대로] | 지금과 **같은 값**으로 setter 호출 → 다시 그리지 않음 |

확인하는 것: `useState` 초기값 · 상태 유지 · 함수형 setter · 같은 값 정책 (P2-11 · P2-12 · P2-14, T-10 · T-14)

### ② 입력창 (`GreetingPanel`)

| 화면 | 동작 |
| --- | --- |
| 이름 입력창 | `onInput`으로 이름 상태를 바꿈, `value`는 상태에서 |
| "안녕하세요, ○○님" | 입력한 이름이 바로 반영 |

확인하는 것: `value` 프로퍼티 · `input` 이벤트, **다른 상태가 바뀌어도**(예: 카운터 클릭) 입력창이 새로 만들어지지 않고 포커스 · 커서 유지 (§4.3)

### ③ 목록 (`TodoPanel` · `TodoRow`)

| 화면 | 동작 |
| --- | --- |
| 할 일 입력창 + [추가] | 항목 추가, id는 카운터로 만들고(`todo-1` …) 지운 번호는 다시 쓰지 않음 |
| 항목 줄: 체크박스 · 글자 · [위로] · [아래로] · [삭제] | 완료 표시(`checked`), 순서 바꾸기, 삭제 |
| "전체 n개 · 완료 m개" | `useMemo`로 계산, 계산 횟수도 기록판에 표시 |

확인하는 것:
- Key 이동: [위로] · [아래로] 뒤 **같은 key의 `<li>` 노드가 그대로**(새로 만들지 않고 MOVE) (§5, Key 확장 화면 시연)
- `checked` 프로퍼티 · `click` 이벤트, 삭제 · 추가 (D-03 · D-04)
- `useMemo`: 목록이 안 바뀌면(예: 카운터 클릭) 다시 계산하지 않음, 바뀌면 다시 계산 (P2-17, T-13)
- props 전달: 루트 목록 상태가 바뀌면 `TodoRow` 화면에 반영 (P2-10, T-16)

### ④ 기록판 (`LogPanel`)

| 화면 | 동작 |
| --- | --- |
| 렌더 횟수 | `App()`이 몇 번 실행됐는지 |
| effect 실행 횟수 | `useEffect`가 몇 번 실행됐는지 |
| memo 계산 횟수 | ③의 `useMemo`가 몇 번 다시 계산했는지 |
| 마지막 update의 patch 줄 수 | 상태 하나만 바꿨을 때 고친 곳이 적은지 (바뀐 곳만 고침) |
| 브라우저 탭 제목 | `useEffect(…, [count])`로 `카운터 3 - Phase 2` 처럼 표시 |

확인하는 것: `useEffect` 실행 조건(의존성 `[count]`), DOM 반영 뒤 실행, 부분 갱신 (P2-16 · P2-18~21, T-12 · T-15)

- 횟수 기록은 렌더 결과에 영향을 주지 않게 **상태가 아닌 바깥 변수**로 센다 (기록하려고 setter를 부르면 렌더가 또 생기므로).

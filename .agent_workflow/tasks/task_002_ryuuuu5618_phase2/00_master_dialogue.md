## 빠르게: 추천안 표

### 묶음 1/5 useState (A: "응" → 추천안 그대로)
1. 여러 useState 구분: hooks 배열에 부른 순서대로 저장, 렌더마다 0번부터
2. if · for 안 Hook 호출: 규칙으로 금지 + 렌더 끝에 Hook 개수가 지난번과 다르면 오류
3. 같은 값 setter: Object.is로 같으면 다시 그리지 않음
4. 함수형 setter c => c + 1: 지원

### 묶음 2/5 useEffect (A: "응" → 추천안 그대로)
1. 실행 시점: patch로 실제 DOM을 고친 직후, 같은 setter 호출 안에서 바로
2. 의존성: 생략 = 매 렌더 뒤, [] = 처음 한 번, [a, b] = 하나라도 바뀌면 (Object.is)
3. cleanup: effect가 돌려준 함수를 다시 실행 직전 · unmount() 때 부름. FunctionComponent에 unmount() 두고 테스트
4. 무한 반복 안전장치: 렌더가 연달아 50번을 넘으면 오류

### 묶음 3/5 useMemo · 기타 Hook (A: "응. 그리고 공부할 때 의존성 개념을 먼저 잡고 가게 도와줘" → 추천안 그대로)
1. useMemo: 처음 계산 · 같은 의존성이면 재사용 · 바뀌면 재계산 · 생략하면 매 렌더 재계산
2. 의존성 비교: 항목마다 Object.is, 배열 길이가 달라지면 바뀜 (effect · memo 공통)
3. 지연 초기화 useState(() => …): 지원, 처음 렌더 때만 실행
4. 자식 컴포넌트가 Hook 호출: 오류 ("Hook은 루트에서만")
- [공부 메모] 2.5단계 체크포인트는 **의존성 개념을 먼저** 잡고 시작 (사용자 요청), 이어서 Q7-1 호출 순서

### 묶음 4/5 입력창 (A: "응" → 추천안 그대로)
1. 지원 프로퍼티: value · checked만. patch는 프로퍼티로(input.value = …), 실제 입력창 값과 다를 때만
2. 입력 이벤트: onInput으로 상태 갱신

### 묶음 5/5 자식 컴포넌트 풀기 · key (A: "응" → 추천안 그대로)
1. 자식 컴포넌트: diff 전에 그 자리에서 실행해 결과 요소로 바꿈(안쪽까지). diff · patch는 요소 · 글자만

3. key = 도형 id, 엔진 카운터(shape-1 …), 지운 번호 재사용 안 함. [위로] · [아래로] = MOVE
4. h() 입력: 숫자 · 문자열 → 글자 노드, null · undefined · boolean 무시, 배열 펼침, key는 props에서 꺼냄

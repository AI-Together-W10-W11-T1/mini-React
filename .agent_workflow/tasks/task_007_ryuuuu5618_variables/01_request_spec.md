## 1. 요청 요약
색 변수(예: Primary = `#0052ff`)를 만들어 두고 버튼 색에 **연결**한다. 변수 값을 한 번 바꾸면 그 변수를 쓰는 버튼이 모두 같이 바뀐다. 「값을 복사해 넣기」와 「이름으로 가리키기」의 차이를 보여 주는 장면이다. 엔진(`packages/`)은 고치지 않는다.

## 2. 확정 요구사항

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| VR-01 | 변수 데이터 | `doc.variables` = 배열 `{ id, name, value }`, 처음 3개: `primary` Primary `#0052ff` · `danger` Danger `#cf202f` · `success` Success `#05b169` (팔레트 색). 순서 = 배열 순서. 추가 · 삭제 · 이름 바꾸기 없음 |
| VR-02 | 연결 표현 | 버튼 `color` 칸에 hex 대신 `'var:<id>'` 문자열을 저장하면 연결. override 규칙 그대로(키가 있으면 override, ↻ = 키 지우기 = 메인 따름). 메인도 연결 가능 |
| VR-03 | 그릴 때 풀기 | 그리기 직전에 순수 함수 `resolveColor(color, variables)`로 hex로 바꿔 `style`에 칠함. 글자색 대비 규칙(task_005)은 푼 hex 기준. 없는 id는 메인 색 → 그래도 없으면 `#0052ff` |
| VR-04 | 변수 패널 | 왼쪽 사이드바 레이어 아래 「변수」 구역: 줄마다 색 칩 · 이름 · 색 입력칸(`<input type="color">`, `input` 이벤트) · hex 글자. 값을 바꾸면 `setDoc` 한 번 |
| VR-05 | 연결 UI | 속성 패널 색 구역에 「변수」 선택 상자: `없음` + 변수 이름들. 고르면 `'var:<id>'` 저장, `없음`이나 팔레트 칩 · 색 입력칸을 고르면 hex로 저장(연결 풀림). 연결 중이면 칩 선택 표시 없음 + 「Primary」처럼 변수 이름 표시 |
| VR-06 | 한 번에 바뀜 | 변수 값을 바꾸면 연결된 버튼(메인을 따르는 인스턴스 포함)만 SET_STYLE, 다른 버튼 · 레이어 노드는 그대로(같은 참조). 렌더 1번 (Batching) |
| VR-07 | Patch · State History | 변수는 `doc` 안이라 task_006 흐름 그대로: [Patch] → 실제 영역엔 푼 색이 들어감, [실행 취소] · [다시 실행]은 변수 값 · 연결까지 두 영역 함께 되돌림 (doc 사본) |
| VR-08 | 기존 동작 유지 | task_004 ~ 006 동작 · 테스트 그대로 (처음 doc의 버튼 색은 hex 그대로라 처음 화면이 같음). Hook은 App에만 7칸 유지, 자식은 props만 |

## 3. 구현 제외 범위
- 변수 추가 · 삭제 · 이름 바꾸기, 색 말고 다른 종류(숫자 · 글자 · 참거짓) 변수, 모드(Light / Dark), 변수끼리 연결(alias)
- 처음 doc에서 미리 연결해 두기 (시연은 직접 연결하며 보여 줌 — 기존 테스트 변경을 줄임)

## 4. 주의사항
- `Color` 타입 주석(FD-20 「소문자 #rrggbb」)이 `'var:<id>'`까지 넓어짐 → 팔레트 · 대비 · 정규화 함수가 `var:`를 hex로 오해하지 않게
- 실제 영역은 DOM에서 읽으므로 푼 hex만 봄 (연결 정보는 doc 사본에만)
- 사용자가 다른 창에서 `index.html` 등 디자인을 고칠 수 있음 → 개발 전 `git status` 확인, 사용자 파일은 커밋 · 되돌리기 하지 않음

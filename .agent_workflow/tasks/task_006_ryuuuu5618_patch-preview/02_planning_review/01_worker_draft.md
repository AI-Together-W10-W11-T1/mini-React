## 0. 코드로 확인한 것 (먼저 읽을 요약)

- **경로 접두는 안 바뀐다.** 실제 영역 구역(`real-section`)을 `div.app`의 **5번째(맨 끝) 자식**으로 두고 자리는 CSS로 정한다 (desktop = 가운데 열 아래 칸, mobile = 속성 패널만 `order`로 뒤로 밀어 캔버스 다음). 그래서 도구 막대 `[0,0]` · 레이어 `[0,1]` · 캔버스 `[0,2]` · 속성 `[0,3]`이 그대로이고 task_005의 patch 기대 표(P-1 ~ 28)는 접두 · 개수 모두 그대로다. 캔버스를 감싸는 열 상자를 새로 만들면 `[0,2]`가 `[0,2,0]`으로 밀려 테스트가 크게 바뀌어서 일부러 안 쓴다.
- **바뀌는 것은 캔버스 안쪽 한 칸뿐**: 「테스트 영역」 제목을 캔버스 첫 자식으로 두면 캔버스 안 경로가 +1 (`B2_PATH` `[0,2,1,1]` → `[0,2,2,1,1]`). patch 종류 · 개수는 그대로.
- **실제 영역의 patch는 별개 표**다 (`qa_todo.md` 「patch 기대 표 — 실제 영역」 R-1 ~ 13): 경로가 영역 상자 안 자식부터라 메인 버튼 `[0,0]` · b1 `[1,0]` …, 이벤트 · key는 DOM에서 안 읽히므로 `SET_EVENT`가 없고 **순서 바꾸기는 `MOVE`가 아니라 위치 비교**로 나온다.
- **Hook 규칙 안에서 정한 방법**: App 기존 5칸 순서는 그대로 두고 뒤에 3칸만 덧붙인다 (`instance.hooks` 5 → 8). ① `useMemo(() => ({ preview: null }), [])` = 보관함(같은 객체를 계속 씀, 렌더를 일으키지 않음 — 엔진에 `useRef`가 없어서) ② `useEffect(…, [])` = 마운트 patch 직후 한 번 DOM에서 세 요소를 찾아 처음 모습을 채우고 `createVDomRoot`를 만들어 보관함에 넣음(렌더 중에는 DOM이 아직 없어서 effect 안에서만) ③ `useState(nav)` = 뒤로 · 앞으로 가능 여부(App state). 엔진 `VDomRoot`에는 「뒤로 갈 수 있나」를 묻는 메서드가 없고 엔진 수정은 금지라서, 앱이 같은 규칙(0번 · 앞쪽 끊음 · 한도 50)으로 위치만 따로 센다. 이 세는 규칙이 엔진과 같은지는 엔진 `History`와 나란히 돌려 비교하는 테스트로 지킨다.
- 실제 영역 상자는 App이 **자식 없는 빈 `<div>`**로만 그린다 (Phase 2 기록판과 같은 방식). 그래서 App이 몇 번 다시 그려도 상자 안 노드를 안 건드린다 — 이것도 단위 테스트로 지킨다 (노드 같은 참조 · 변경 0).

## ③ 안 덮이는 것

- **깜빡임이 사라지는 시간 · 색감 · 움직임의 부드러움** (명세 주의 4): 「박스가 생겼다 · 바뀐 노드 위에 있다 · 안 바뀐 노드 위에는 없다」만 본다. 육안은 QA 캡처 단계.
- **patch 도중 예외 처리**: 엔진이 실제 영역을 마지막 기록으로 복구하고 예외를 던지지만 이 task는 알림창 등을 정의하지 않았다. 앱은 따로 안 잡고(예외는 콘솔로) 정리된 DOM에서는 거의 나올 수 없어 시나리오를 만들지 않았다. 필요하면 명세를 더해야 한다.
- **D-05(노드 교체)의 화면 시나리오**: 캔버스 흐름에는 노드 종류가 바뀌는 장면이 없어 연결 모듈 단위 테스트(R-13)로만 본다. 엔진 D-01 ~ 05 전체는 엔진 단위 테스트가 이미 덮음.
- **실제 영역에서 key 이동(`MOVE`)**: DOM에서 key가 안 읽혀 위치 비교로 나온다 (엔진 정상 동작). key 이동 시연은 Phase 2 목록 · 엔진 단위 테스트 몫이다.
- 구현 제외 범위: 테스트 영역을 실제 영역 기록으로 되돌리기, 실제 영역에서 고르기 · 편집, patch 목록 · 줄 수 표시.
- 한도 50은 e2e에서 한 건(QA-A36)만 돌리고 나머지는 `previewNav` 대조 테스트가 지킨다. 스크린리더 · Chromium 밖 브라우저 · 실제 터치 입력은 범위 밖 (mobile은 기존처럼 화면 크기 + 터치 에뮬레이션).

## ④ 정해야 할 것 (모두 추천이 있다 — 「추천대로」면 그대로 진행)

1. **「테스트 영역」 머리글을 어디에 둘까**
   - 추천: 캔버스 안 첫 칸에 진짜 제목(`<h2>`)을 둔다. 장점: 글자를 화면에서도 · 테스트에서도 읽을 수 있고 「실제 영역」 머리글과 같은 모양. 대가: 캔버스 안 경로가 한 칸 밀려 테스트 숫자 4곳(`B2_PATH`)을 고침, 실제 영역으로 복사할 때 이 제목은 정리 함수가 뺌.
   - 대안: CSS로만 글자를 그림(DOM 변화 0). 대가: 글자가 화면에만 있어 테스트로 못 읽고 진짜 제목 요소가 아님.
